And the locations refer to page (starting with 1 as the page where the sheet music begins, so the
title pages are not counted) and then row in parentheses. The dense vertical lines
consisting of the katakana ro, tsu, re, chi, ha and hi (and sometimes others) are rows,
and markings refer to the line to the left of them, so the row can be determined by
counting those dense vertical clusters of ro, tsu, re, chi, ha, hi etc. that are to the
right of that marking, and adding one.

The katakana for ro, tsu, re chi, ha, hi, and the lines and circles that repeats
often next to or between them are not extra markings, but when there are such characters as
in the map above marked into the sheet music, if possible populate the marking list in the yaml with
them and their locations.

The name is likely written in large characters on the front page,
along with the writer. The name then repeats on the left at the beginning
of the piece on the second page. Under that the composer's name might be written.
The composer is most often Ueda Hōdō = 上田芳憧. And the writer could most likely be either
上田佳憧 = Ueda Kadō or 上田芳誠 = Ueda Hōsei

There could be notes on performance etc. atteched under the composers name and/or in the
end of the piece. These should be collected to orig_notes and translated to
trans_notes. The orig_extra_notes can possibly be found under the piece's name in the third attached document, 上田流本曲解説.pdf
those should be put to the yaml and translated under extra_notes

At the beginning of the first page, shamisen and koto tunings may be marked, or possibly just one of them.
Use the format below

{Instrument} in {tuning type} tuning:\n1st string = {string1}\ns2nd string = {string2}\n3rd string = {string3}
The tuning of each string corresponds to the katakana next to the numerical kanji sign. So if for shamisen it says for instance:
三弦
ロ　一
レ　二
ハ　三
(三上り)

The output for shamisen_tuning should be:
Shamisen in san-agari tuning:\n1st string = RO\ns2nd string = RE\n3rd string = HA
Use romaji for the katakana and in capital letters.
Even if you are not sure what each string corresponds to in the pdf, just write your best guess.
Also dont forget to write this for both shamisen and koto, too into koto_tuning

If tuning seems to be missing for both koto and shamisen, but piece type is jiuta, write:
Shamisen in hon-chōshi tuning:\n1st string = RO\ns2nd string = RE\n3rd string = RO
and
Koto in hirajōshi tuning:\n1st string = RE\ns2nd string = HA\n3rd string = RO
If the type of piece is sokyoku, but no tunings are found, just write the koto tuning.


If there are two or more pieces in the sheet, you can write both of them with the piece name like:
Kurokami:Shamisen in san-agari tuning.... Asatode: Shamisen in honchōshi tuning...

Also write out the parts of the yaml where there is no value to be found, and leave the valua blank, just like
in the reference yaml.

The values in the yaml that are Japanese such as the composer name etc. should be written in romaji,
except japanese_name, orig_notes and orig_extra_notes.

Make sure to use the Hepburn system of romanization so that a long o in Japanese would be romanized as ō and a long u as ū

In those cases the name would be all the piece names, comma separated, like Kurokami, Asatode and the orig lyrics and trans lyrics should include both, one after another.

If there is a json with lyrics included together with this prompt, those are the lyrics for the piece to be added to orig_lyrics and translated to trans_lyrics.
The sheet may also include the lyrics written in red next to the notes (ro, tsu, re chi) and so on, but the ones in the json are more trustworthy, if provided.
The ones written in red in the sheet music could be used for reference if there is something unclear in the lyrics in the json, but as they are in calligraphy and hard to
decipher correctly, always trust the json lyrics over those.
